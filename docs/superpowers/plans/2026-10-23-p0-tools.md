# P0 工具补全 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 补齐 P0 缺口：可查目标、可查体检、可按条目精确删除、日总结含钠/糖/饮水/运动/步数，并修掉删除后本地 journal 不清理的正确性问题。

**Architecture:** 全部改动集中在单文件 `mfp_adapter.py`（项目既有结构）：adapter 层新增/扩展取数方法（网页 water、目标解析），工具层新增 3 个 MCP tool 并修正 2 个既有 tool 的口径。测试沿用 `tests/conftest.py` 的 `adapter` / `mock_get_adapter` 双 fixture。所有新工具只读或幂等，不改变既有写入路径。

**Tech Stack:** Python 3.10+、FastMCP、requests、pytest、ruff、mypy

**Spec:** 本文件（上一轮会话产出的工具审计结论，P0 清单 = 第 4 节 1/2/3/4 条）

## Global Constraints

- 一文件一提交；commit message 中英双语，英文块在前。
- `ruff check mfp_adapter.py tests/` 与 `mypy mfp_adapter.py` 必须无告警。
- 全量 `pytest` 必须绿；覆盖率 `fail_under = 85`。
- 工具描述沿用现有中英双语 + `Args:` 段落格式。
- 不读取、不打印 `cookies.json` 内容；验证脚本通过覆盖 `MFPAdapter.COOKIES_FILE` 指向主 checkout。
- 错误返回统一为中文短句，前缀与现有工具一致（`错误:` / `获取…失败:` / `…失败:`）。

## Review Focus

- 删除一条食物后，`nutrition_journal.json` 里对应项必须消失，重复营养不得再进趋势。
- 目标取不到时，日总结必须显式标注「默认值」，不得静默使用 2800/210/280/93。
- `diary_meal` 与 `food_entry` 同时存在时，热量/宏量只能计一次。
- 精确删除传错误 id / 不存在的名字时，必须报错且不误删其它条目。
- 任何新工具在会话过期时返回可操作的提示（指向 `get_cookie_guide`），不得抛栈。
